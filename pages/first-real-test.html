Project structure

A minimal but realistic layout. The important rule: conftest.py lives with the tests it serves, because Pytest resolves fixtures by directory.

folder layout
playwright-python-framework/ ├── tests/ │ ├── conftest.py      # shared fixtures — browser, login, test data │ ├── test_login.py    # login/auth scenarios │ └── test_products.py# cart/checkout scenarios ├── pytest.ini         # markers + default CLI options └── requirements.txt   # pytest, pytest-playwright
Why tests/ has its own conftest Pytest looks for a fixture in the test's own file first, then in conftest.py in the same directory (and parent directories). Putting it inside tests/ means every test file in that folder shares those fixtures without importing anything.

conftest.py

This is where everything from the fixtures page actually gets used. Note that page here is the fixture provided free by pytest-playwright — these custom fixtures build on top of it rather than replacing it.

tests/conftest.py
import pytest from playwright.sync_api import Page BASE_URL = "https://rahulshettyacademy.com/loginpagePractise/" @pytest.fixture(scope="session") def credentials():     """Test data in one place — not hardcoded in every test."""     return {"username": "rahulshettyacademy", "password": "learning"} @pytest.fixture def login_page(page: Page):     """Fresh login page before each test that asks for it."""     page.goto(BASE_URL)     yield page     # teardown: pytest-playwright closes the context itself,     # so there is nothing to clean up here. @pytest.fixture def logged_in_page(login_page: Page, credentials):     """Signs in once, so authenticated tests don't repeat these 3 lines."""     login_page.get_by_label("Username").fill(credentials["username"])     login_page.get_by_label("Password").fill(credentials["password"])     login_page.get_by_role("button", name="Sign In").click()     return login_page

Three things worth noticing, because they're exactly what an interviewer probes:

  • Fixtures depending on fixtures. logged_in_page takes login_page, which takes page. Pytest resolves that whole chain automatically — you never call them manually.
  • Data lives in a fixture, not the test. Change the password once in credentials instead of in fifteen test files.
  • yield vs return. login_page uses yield because it has a teardown phase conceptually; logged_in_page just returns because it has nothing to undo.

The test file

Now the payoff — the tests themselves are tiny, because setup lives in fixtures and Playwright's auto-waiting removes every explicit wait.

tests/test_login.py
import pytest from playwright.sync_api import Page, expect @pytest.mark.smoke def test_invalid_credentials_shows_error(login_page: Page):     login_page.get_by_label("Username").fill("wrong_user")     login_page.get_by_label("Password").fill("wrong_pass")     login_page.get_by_role("button", name="Sign In").click()     # no wait needed — expect() retries until it appears or times out     expect(         login_page.get_by_text("Incorrect username or password.")     ).to_be_visible() @pytest.mark.smoke def test_valid_login_reaches_shop(logged_in_page: Page):     # the fixture already signed in — this test only asserts the outcome     expect(logged_in_page.get_by_role("heading", name="Shop Name")).to_be_visible() def test_add_two_products_to_cart(logged_in_page: Page):     for product in ["iphone X", "Blackberry"]:         # find by name, not position — survives re-ordering         card = logged_in_page.locator("app-card").filter(has_text=product)         card.get_by_role("button", name="Add").click()     logged_in_page.get_by_role("button", name="Checkout").click()     expect(logged_in_page.locator("h4.media-heading")).to_have_count(2)
What makes this "senior-looking" code Zero time.sleep(). Zero hardcoded indexes. Credentials injected rather than inline. Setup shared via fixtures instead of copy-pasted. Assertions are web-first (expect), not bare Python assert on a snapshot value. Those five properties are what a reviewer scans for.

pytest.ini

Registers your custom markers (otherwise Pytest warns about unknown marks) and sets default CLI options so you don't retype them.

pytest.ini
[pytest] markers =     smoke: quick critical-path checks     regression: full suite, slower # applied to every run unless overridden on the command line addopts = -v
Keep --headed out of the config file Tempting to add --headed here, but it will then also run headed in CI, which usually has no display. Pass it ad-hoc when debugging instead.

Running it

Every command from the Pytest page, now against this actual project:

CommandWhat it does
pytestRuns every test_*.py found from the current directory down
pytest -sSame, but shows print() output
pytest tests/test_login.pyJust that one file
pytest tests/test_login.py::test_valid_login_reaches_shopOne specific test function
pytest -m smokeOnly tests marked @pytest.mark.smoke
pytest --headedWatch the browser instead of running headless
pytest --headed --slowmo 500Headed + half-second pause between actions — the debugging combo
pytest --browser firefoxRun against Firefox instead of Chromium (plugin flag — no code change needed)
Beyond this video — debugging tools you'll be asked about pytest --tracing on records a trace file you can open with playwright show-trace trace.zip — a full timeline with DOM snapshots per step. PWDEBUG=1 pytest opens Playwright Inspector to step through a test live. And page.pause() dropped into a test halts execution there with the Inspector open. If asked "how do you debug a failing Playwright test," these three are the expected answer.

Interview Q&A

Mid Walk me through how you'd structure a Playwright + Pytest project from scratch.
A tests/ directory holding the test files plus a conftest.py for shared fixtures (browser/page setup, login, test data), a pytest.ini registering custom markers and default options, and requirements.txt pinning pytest and pytest-playwright. Fixtures go in conftest so they're shared by directory without imports; test data lives in fixtures rather than hardcoded in tests; and page interactions use semantic locators so tests survive UI churn.
Mid A fixture depends on another fixture. How does Pytest resolve that?
Automatically, by name. logged_in_page declares login_page as a parameter, which itself declares page. Pytest walks that dependency chain and builds them in order before the test body runs — you never instantiate them yourself. Each is also cached per its scope, so a session-scoped dependency isn't rebuilt for every consumer.
Senior Why put login in a fixture rather than a helper function you call at the top of each test?
Three reasons. Scope control — a fixture can be session/module scoped to avoid repeating expensive setup, a plain function can't. Automatic teardown — yield gives you guaranteed cleanup even if the test fails, whereas a helper's cleanup is skipped on exception unless you wrap everything in try/finally. And composability — other fixtures can depend on it, letting Pytest build a dependency graph rather than you sequencing calls by hand.
Senior How would you debug a Playwright test that fails only in CI?
Run with --tracing on so CI produces a trace artifact, then open it locally with playwright show-trace — it gives per-step DOM snapshots, network activity and console logs from the actual failing run. Locally, reproduce with --headed --slowmo or drop a page.pause() to step through with Inspector. Also check for the classic CI-only causes: different viewport size, missing --headed display assumptions, timezone/locale differences, and test-ordering dependencies exposed by parallel execution.
Junior How do you run only a subset of tests?
By file (pytest tests/test_login.py), by single function using the double-colon syntax (pytest tests/test_login.py::test_name), or by marker (pytest -m smoke) after tagging tests with @pytest.mark.smoke and registering that marker in pytest.ini.
Senior Your suite has 40 tests and each one logs in through the UI. It takes 25 minutes. How do you speed it up?
Stop logging in through the UI repeatedly. Authenticate once, save the session with context.storage_state(path="state.json"), and have tests start from a context created with that stored state — turning a multi-second UI login into a near-instant state load. Beyond that: run tests in parallel with pytest-xdist (-n auto), keep the browser session-scoped rather than per-test, and reserve full UI login for the handful of tests actually testing login itself.

Gotchas

Unregistered markers warn Using @pytest.mark.smoke without declaring smoke under markers in pytest.ini produces a PytestUnknownMarkWarning on every run. It still works — but it's noisy, and a typo'd marker name fails silently by matching nothing.
conftest.py is resolved by location, not import You never import conftest. If fixtures aren't being found, the usual cause is the file sitting in the wrong directory relative to the tests, or being named something other than exactly conftest.py.
