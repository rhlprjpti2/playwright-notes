Environment Setup: Python, Pip & PyCharm

Installing Python and PyCharm is the easy part — the part worth actually understanding is why the IDE's interpreter has to stay in sync with your system's Python, and what pip is actually doing when you install packages.

Concept

The setup has three layers: install Python itself, install the PyCharm IDE, and make sure PyCharm's project interpreter points at the same Python installation as your system/terminal. That last part matters more than it looks — packages installed via pip from the terminal live inside a specific Python installation's folder. If PyCharm is configured to use a different interpreter, those packages simply won't show up in the project, and you'd have to install them again through the IDE.

What is pip

Pip is Python's package installer — it ships bundled with Python, so installing Python also gives you pip. When you need an external library (in this course, the Playwright package), pip is the tool that downloads it.

Cross-language mapping, since the concept exists everywhere under a different name:

  • Java calls them jars (e.g. Selenium jars, Playwright jars)
  • JavaScript calls them node packages
  • Python calls them simply packages
Two installs, not one pip install pytest-playwright installs the Python plugin/package. It does not download the actual browser engines. That's a separate step: playwright install, which pulls the Chromium/Firefox/WebKit binaries the tests will actually drive.
Beyond this video — virtual environments The course installs packages directly into the system-wide Python install. In real projects (and in most interviews), packages are installed into a virtual environment instead — an isolated, per-project copy of Python + its own package set, so different projects can depend on different (even conflicting) package versions without interfering with each other. 
python -m venv .venv
.venv\Scripts\activate      # Windows
source .venv/bin/activate   # Mac/Linux
pip install pytest-playwright
Once activated, pip/python inside that terminal session point at the venv, not the system install — and PyCharm's "custom environment → existing" interpreter picker (covered above) can point at a venv's Python executable exactly the same way it points at a system one.

Interview Q&A

Junior What is pip, and how does it relate to concepts in other languages?
Pip is Python's built-in package installer/manager, bundled with every Python install. It's the equivalent of downloading jars in Java or installing node packages in JavaScript — Python just calls the downloaded external libraries "packages."
Junior Why does Playwright for Python need a separate Pytest plugin?
Playwright's Python tests are written on top of the Pytest testing framework/engine. The pytest-playwright plugin is what makes Pytest actually recognize and execute Playwright-based test code — without it, Pytest has no built-in awareness of Playwright.
Junior What's the difference between `pip install pytest-playwright` and `playwright install`?
The pip command installs the Python package/plugin itself. playwright install is a separate step that downloads the actual browser engine binaries (Chromium, Firefox, WebKit) that your tests run against — installing the plugin doesn't get you the browsers.
Mid Why does keeping the IDE's interpreter in sync with the system Python matter?
Packages installed via pip are stored inside whatever Python installation pip is attached to. If PyCharm's project interpreter points at a different Python installation than the one you used in the terminal, packages you installed from the terminal won't appear in the project — you'd have to reinstall them again through the IDE, or vice versa. Pointing both at the same interpreter keeps everything in sync regardless of where you install from.
Junior On a Mac, why use `which python3` / `pip3` instead of `which python` / `pip`?
Mac machines ship with Python 2 pre-installed by default. Plain `python`/`pip` commands can resolve to that legacy Python 2 rather than the Python 3 you separately installed, so Mac users should explicitly use the `python3`/`pip3` variants to target the right version. Windows machines don't have this issue since they don't ship with a default Python.
Mid Why use a virtual environment instead of installing packages system-wide?
Isolation. Each project gets its own copy of Python plus its own independent set of installed packages, so Project A needing pytest-playwright==0.5.2 and Project B needing a different version don't conflict. It also keeps a machine's system Python clean and makes a project's exact dependencies reproducible on another machine.

Gotchas

Watch out On Mac, don't assume python/pip point to your newly installed Python 3 — verify with which python3 first, since the system's built-in Python 2 can silently intercept the plain command.
Watch out Newer PyCharm versions merged the separate "project name" and "project location" fields into a single path field — if you're following older instructions or screenshots, this can be confusing when creating a new project.
