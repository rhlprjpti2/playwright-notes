Concept

The course assumes no prior experience with any technology and builds up in a strict dependency order: Python fundamentals first, then Pytest — because Playwright's Python tests are built directly on top of the Pytest framework, so Pytest knowledge is a prerequisite, not an optional side topic.

From there it moves to hands-on UI automation covering every major web component, then API automation with network interception (intercepting requests/responses to test edge cases), then a full framework-building phase, an optional BDD layer, and finally CI/CD integration with Jenkins.

Interview Q&A

Junior Why learn Pytest before Playwright, specifically?
Playwright's Python test support is built directly on the Pytest framework — Pytest isn't a separate, optional tool alongside Playwright, it's the foundation the tests actually run on. Skipping it means not understanding fixtures, test discovery, and assertions that Playwright-Python code relies on.
Mid What does "framework design" cover beyond writing individual test scripts?
Data-driven testing, parameterization, running tests in parallel or in groups, logging, reporting, automatic screenshots, and the Page Object Model design pattern for maintainable test code.
Mid How does BDD fit into a Playwright + Pytest framework?
Through a separate Pytest plugin that lets you write Gherkin feature files, bringing Cucumber-style behavior-driven development on top of the existing Pytest/Playwright framework — it's layered on, not a replacement.
Junior Where does Jenkins fit in?
Once the framework and tests are built, Jenkins is used as the CI/CD tool to integrate the framework and schedule automated test job runs.

Gotchas

Terminology precision "API automation" and "network interception" are named as related but distinct ideas in this course — interception specifically means intercepting requests/responses (e.g. to mock or inspect them) for edge-case testing, not just calling an API endpoint directly in a test.
