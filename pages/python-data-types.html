Core Data Types

The five types you'll use in nearly every script: int, float, str, bool, None. The interesting part isn't the list — it's the handful of behaviors around them that surprise people coming from other languages.

All five are immutable — reinforcing the pattern from the Memory Model page: reassigning a variable of any of these types never mutates the old object, it rebinds the name to a new one.

type() vs isinstance()

type(5) == int          # True
isinstance(5, int)      # True — but prefer this one

isinstance() is idiomatic Python for a reason that matters once inheritance enters the picture: it respects subclasses, while type() == does not.

class Animal: pass
class Dog(Animal): pass

d = Dog()
isinstance(d, Animal)      # True  — Dog IS an Animal
type(d) == Animal          # False — type(d) is exactly Dog, not Animal
The bool/int connection, made visible bool is a subclass of int — True == 1 and False == 0 are both True, and isinstance(True, int) is True too. This is a genuine language design choice (booleans arrived late in Python's history and were bolted onto the existing int type), and it's a favorite "did you know" interview question.

Truthy and falsy

Every object in Python has an implicit boolean value, used whenever it appears where a condition is expected — if some_value: — without needing == True anywhere. This is why idiomatic Python reads if my_list: rather than if len(my_list) > 0:.

Falsy (evaluate to False)Truthy (everything else)
0, 0.0Any non-zero number

results = []
if results:              # False — empty list is falsy
    print("has results")
else:
    print("empty")        # this runs

None specifically

None represents "no value" — Python's equivalent of null. It's the default return value of any function that doesn't explicitly return something, and the idiomatic default for "optional" function parameters (see the mutable-default-argument fix on the Memory Model page, which relies on exactly this).

def no_return():
    x = 1 + 1
    # no return statement

print(no_return())    # None

Always compare with is None, not == None — covered in depth on the Memory Model page, but worth repeating: None is a singleton, so identity comparison is both idiomatic and safe from custom __eq__ surprises.

No silent type coercion

Coming from JavaScript, this is one of the first genuine surprises. JavaScript will happily coerce types across an operator; Python raises an error instead:

"3" + 3
# TypeError: can only concatenate str (not "int") to str

You must convert explicitly:

int("3") + 3        # 6
str(3) + "3"         # "33"

The one exception: numeric types do mix freely, because Python defines a clear promotion rule between them — int combined with float always promotes to float:

3 + 2.5      # 5.5  (float)
type(3 + 2.5)  # <class 'float'>

Interview Q&A

Junior Why prefer isinstance() over type() == for type checks?
isinstance() accounts for inheritance — it returns True if the object is an instance of the class or any subclass of it. type(x) == SomeClass only matches the exact type, so it silently breaks for subclasses. isinstance() also accepts a tuple of types for an "or" check: isinstance(x, (int, float)).
Junior What values are falsy in Python?
Zero of any numeric type (0, 0.0), empty sequences and collections ("", [], {}, (), set()), and None. Everything else — including any non-empty string, non-zero number, or non-empty collection — is truthy. This is why if my_list: is idiomatic for "does this list have anything in it."
Mid Is bool actually a separate type from int in Python?
No — bool is a subclass of int. True and False behave as 1 and 0 in arithmetic contexts (True + True == 2), and isinstance(True, int) is True. This is a real design quirk from Python's history, not a common misconception to dismiss — it genuinely works this way.
Mid Why does "3" + 3 raise an error in Python but work in JavaScript?
Python does not perform implicit type coercion across incompatible types — str and int have no defined + relationship, so it raises TypeError rather than guessing an interpretation. JavaScript's + coerces the number to a string and concatenates. Python requires an explicit conversion (int("3") + 3 or str(3) + "3") — a deliberate design choice favoring predictability over convenience.
Senior What actually distinguishes None from other "empty" values like 0, "", or []?
None represents the absence of a value, not an empty instance of some type — there's no meaningful "type" to it beyond NoneType. Practically: a function returning None is signaling "nothing to return" (e.g. a lookup that found nothing), which is semantically different from returning an empty list (a lookup that found zero matching items, but the operation itself succeeded and produced a valid, typed result). Conflating the two — e.g. returning None instead of an empty list from a search function — forces every caller to add a None-check before it can safely iterate, which a consistently-typed empty collection wouldn't require.

Gotchas

Float rounding is not a Python-specific bug 0.1 + 0.2 == 0.3 is False in Python — and in virtually every language using IEEE 754 binary floating point, because 0.1 and 0.2 can't be represented exactly in binary. For exact decimal arithmetic (money, for instance), use the decimal module instead of float.
Empty containers are falsy but not None if some_list: and if some_list is not None: are not equivalent — an empty list is falsy but is not None. Confusing these two checks is a common source of subtle bugs when a function might return either None ("nothing found") or an empty list ("search succeeded, zero results").
