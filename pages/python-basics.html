Python Basics

The absolute minimum syntax needed before touching Playwright code: printing, comments, and — the one thing that trips up people coming from typed languages — variables with no declared type.

Concept

print("Hello") writes to the console — the equivalent of Java's System.out.println. Comments start with #; everything after it on that line is ignored by the interpreter.

Variables need no declared type: a = 3 is a complete, valid declaration. Unlike Java (int a = 3;), Python figures out the data type at runtime from whatever value you assign — the data types still exist under the hood, they're just never written explicitly at the point of declaration.

Multiple variables can be declared and assigned on a single line: b, c, d = 5, 6.4, "great" — values are assigned respectively, in the order given, without needing three separate lines.

Beyond this video — checking the type Python inferred The course says types exist but aren't declared. The natural follow-up an interviewer may ask is how you'd see the inferred type — type(c) returns it at runtime (<class 'float'>). The core built-in types you'll meet immediately: int, float, str, bool. Python is dynamically typed (type determined at runtime, and a variable can later be reassigned to a different type) but also strongly typed (it won't silently coerce "5" + 5 — that raises a TypeError). That distinction is a common interview question, and "dynamically typed" alone is only half the answer.

Interview Q&A

Junior Does Python require you to declare a variable's data type?
No. Python is dynamically typed — you write a = 3 with no type annotation, and the interpreter determines the data type from the assigned value at runtime. Data types still exist internally; they're just never declared explicitly at the point of creation, unlike Java's int a = 3;.
Junior How do you declare multiple variables on a single line, and why would you?
b, c, d = 5, 6.4, "great" assigns each value to the corresponding variable in order, avoiding three separate declaration lines for related values.
Junior What character starts a comment in Python?
The hash character #. Everything after it on that line is ignored by the interpreter.

Gotchas

Watch out PyCharm may flag missing whitespace (e.g. around =) as a code-style warning. That's a cosmetic formatting nag from the editor, not a syntax error — the code still runs without it. Don't conflate this with Python's actual indentation-based block structure (where whitespace at the start of a line is functionally significant for scoping) — that's a separate, stricter rule this lecture didn't get into yet.
