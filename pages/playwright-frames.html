Frames & iFrames

An iframe is a whole separate HTML document embedded inside the page. Visually it looks like part of the page; structurally it isn't, so page.locator() can't see into it. frame_locator() is how you cross that boundary.

What a frame actually is

An <iframe> embeds an entirely separate HTML document inside the current one. The two share screen space but not structure — the embedded page has its own <html>, its own <body>, and its own DOM tree. News sites, embedded video players, payment forms and third-party widgets are all commonly iframes.

Because page.locator() only queries the parent document, an element inside a frame is invisible to it — the search finds nothing and, thanks to auto-waiting, retries until it times out. Same failure signature as using the wrong page object for a popup, and for the same underlying reason: wrong document.

Using frame_locator()

# Identify the frame itself, then work inside it
page_frame = page.frame_locator("#courses-iframe")

page_frame.get_by_role("link", name="All Access Plan").click()

Two things worth noting:

  • Use frame_locator(), not locator(), to select the frame. page.locator("#courses-iframe") would match the <iframe> element itself as an object on the parent page — it does not give you access to its contents. frame_locator() specifically means "enter this frame."
  • Every element inside must go through the frame object. Once you have page_frame, all locators chain off it. Reverting to page. puts you straight back in the parent document — the two coexist, and you switch by choosing which object to call.
Beyond this video — related APIs frame_locator() is the modern, auto-waiting-aware approach and should be the default. Older APIs still appear in existing codebases: page.frame(name="...") and page.frame(url="...") return a Frame object, and page.frames lists every frame on the page. Frames also nest — for a frame inside a frame, chain them: page.frame_locator("#outer").frame_locator("#inner").locator("button").

Asserting on whole-page text

To check that some text appears anywhere in a document without knowing which element holds it, target body — which wraps the entire document — and assert it contains the text:

expect(page_frame.locator("body")).to_contain_text("happy subscribers")

This is a genuinely different assertion shape from what's covered on the Auto-Waiting page, and the distinction is worth being precise about:

ApproachAsksBest when
expect(get_by_text("x")).to_be_visible()"Find the element containing this text — is it visible?"You care that a specific element is displayed
expect(locator("body")).to_contain_text("x")"Within this region, does this text appear anywhere?"You don't know or care which element holds it
to_contain_text vs to_have_text to_contain_text() is a substring match — passes if the text appears anywhere within. to_have_text() requires the element's full text to match exactly. On a body locator you almost always want to_contain_text(), since the exact full text of an entire document is never what you're asserting.

Interview Q&A

Junior What is an iframe and why can't a normal locator find elements inside one?
An iframe embeds a completely separate HTML document inside the current page — its own html, body and DOM tree. page.locator() only queries the parent document, so anything inside the frame is outside its search scope. You cross the boundary with page.frame_locator(selector), then chain locators off that.
Mid What's the difference between page.locator("#frame") and page.frame_locator("#frame")?
locator() matches the <iframe> element itself as an object sitting in the parent document — useful for checking the frame exists or its dimensions, but it gives no access to the content inside. frame_locator() means "enter this frame": subsequent locators chained off it query the embedded document instead of the parent.
Mid After working inside a frame, how do you get back to the main page?
You don't "switch back" — there's no modal state to reset. The page object always refers to the parent document and the frame object always refers to the frame; both remain valid simultaneously. Calling page.locator(...) queries the parent, calling page_frame.locator(...) queries the frame. (This differs from Selenium, where switch_to.frame() changes driver state and requires an explicit switch_to.default_content() to return.)
Junior How do you assert that some text appears anywhere on a page?
Target the body element — which wraps the whole document — and use a substring assertion: expect(page.locator("body")).to_contain_text("happy subscribers"). Use to_contain_text() rather than to_have_text(), since the latter requires the element's entire text to match exactly.
Scenario An element is clearly visible on screen, but your locator times out saying it doesn't exist. What do you check?
Visible-but-unreachable almost always means wrong document. Check whether the element sits inside an <iframe> (needs frame_locator()), inside a popup window opened by an earlier click (needs the child page object from expect_popup()), or whether it's a native browser dialog (not in any DOM — needs page.on("dialog")). Inspecting the element and looking for an iframe ancestor in the DOM tree settles it quickly. If none of those apply, then consider timing or an incorrect selector.
Senior How do you handle an element inside a frame that's nested within another frame?
Chain frame_locator() calls, one per level: page.frame_locator("#outer").frame_locator("#inner").locator("button"). Each call descends one document deeper. Worth noting frames can load asynchronously and independently of the parent — frame_locator() participates in auto-waiting, so it handles a frame that hasn't loaded yet, but a frame whose src is slow can still surface as a timeout on the inner locator rather than an obvious frame-level error.

Gotchas

The confusing failure mode An element inside a frame produces a plain "not found" timeout — not an error mentioning frames. Since the element is visibly on screen, this is genuinely disorienting the first time. If a locator fails for something you can plainly see, check for an iframe ancestor before anything else.
Don't select the frame with locator() page.locator("#my-frame").locator("button") looks reasonable but fails — it's searching for a button inside the iframe element as rendered in the parent document, which contains nothing. Only frame_locator() crosses into the embedded document.
